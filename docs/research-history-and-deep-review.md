## Editing and history

Property accounts now have database-backed versions. Administrators can edit prose, timelines, references, uncertainties, related names and map evidence. A reason is required. Version checks prevent one editor silently overwriting another. Existing image credits and profile connections are retained.

Members can inspect a property’s history, compare changes and read a complete saved version. Administrators can restore an earlier account as a new version; previous versions remain intact. The system history page offers filtering and an activity feed. Database triggers capture changes to 21 record types atomically with the change, including profiles, relationships, events, media, notes, places, imports and accounts. Historical snapshots are append-only.

Account credentials and account contact values are excluded from snapshots. Protected account changes retain field names only. Direct database writes without application context are explicitly unattributed. History begins with the imported baseline and this release: it cannot reconstruct previously unrecorded edits. Older application activity entries remain available separately.

## Verification

Local verification covered an actual edit, comparison and restore; stale writes; immutable history; atomic rollback; credential redaction and password-only change metadata; administrator, member and anonymous access; narrow mobile layouts; all property routes and local images. Live schema changes followed a readable database backup. Research publication refuses to overwrite content that differs from both the expected baseline and the reviewed version.
